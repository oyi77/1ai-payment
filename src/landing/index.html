KeandalanReliability

Membosankan di productionBoring in production

Bagian menarik dari pembayaran terjadi sekali, di kode kami — bukan tiap kali ada yang rusak jam 2 pagi di kode Anda. The interesting part of payments happens once, in our code — not every time something breaks at 2am in yours.

↻

Retry + dead-letterRetry + dead-letter

Webhook yang gagal dicoba 3× (5s, 30s, 300s). Setelah habis, event masuk dead-letter dan bisa di-replay dari dashboard.Failed webhooks are retried 3× (5s, 30s, 300s). Once exhausted, the event lands in the dead-letter queue and can be replayed from the dashboard.

🔐

HMAC + timing-safeHMAC + timing-safe

Setiap callback diteruskan dengan header X-Payment-Signature (HMAC-SHA256). Verifikasi gateway memakai perbandingan timing-safe.Every forwarded callback carries an X-Payment-Signature header (HMAC-SHA256). Gateway verification uses timing-safe comparison.

🧾

IdempotenIdempotent

idempotency_key dijaga UNIQUE index per merchant, dan callback duplikat ditolak di level database — bukan hanya dicek di kode.idempotency_key is backed by a per-merchant UNIQUE index, and duplicate callbacks are rejected at the database level — not only checked in code.

🔒

Isolasi merchantMerchant isolation

API key merchant-scoped dan rate limit terpisah. Kredensial gateway yang Anda simpan dienkripsi AES-256-GCM.Merchant-scoped API keys and separate rate limits. Gateway credentials you save are encrypted with AES-256-GCM.

🛡

Callback URL dijaga SSRFSSRF-guarded callbacks

URL callback divalidasi per percobaan dan setiap redirect hop, sehingga server tidak bisa dipakai memanggil jaringan internal.Callback URLs are validated per attempt and on every redirect hop, so the server cannot be used to reach internal networks.

📖

OpenAPIOpenAPI

Spesifikasi OpenAPI 3.1 di-generate dari kode. Setiap endpoint bisa dicoba dari /reference.The OpenAPI 3.1 spec is generated from code. Every endpoint is testable from /reference.

FAQ

Pertanyaan yang sering munculQuestions we actually get

Apa yang terjadi kalau satu gateway mati?What happens if one gateway goes down?
Integrasi Anda tidak terikat gateway: ganti nilai gateway pada request berikutnya dan transaksi lewat jalur lain. Kode checkout Anda tidak berubah. Perlu dicatat: failover antar-gateway tidak otomatis — pemilihan gateway ada di sisi Anda.Your integration is not gateway-bound: change the gateway value on the next request and the transaction takes another path. Your checkout code does not change. Note that cross-gateway failover is not automatic — gateway selection is yours.
Di mana data saya disimpan?Where is my data stored?
Database LibSQL di infrastruktur kami, terisolasi per merchant. Order dan event webhook ternormalisasi disimpan untuk audit dan replay — termasuk payload mentah callback dan header-nya, yang dipakai untuk investigasi dan replay. Kredensial gateway yang Anda simpan dienkripsi AES-256-GCM; API key disimpan sebagai hash SHA-256.LibSQL on our infrastructure, scoped per merchant. Orders and normalized webhook events are stored for audit and replay — including the raw callback payload and its headers, which back investigation and replay. Gateway credentials you save are encrypted with AES-256-GCM; API keys are stored as SHA-256 hashes.
Apakah ini relevan dengan PCI?Is this PCI-relevant?
Kami tidak menyimpan, memproses, atau mentransmisikan nomor kartu. Data bayar mengalir dari pelanggan langsung ke gateway; kami hanya menerima payment URL dan callback status. Konsultasikan QSA Anda untuk pemetaan yang berlaku pada bisnis Anda.We do not store, process, or transmit card numbers. Payment data flows from the customer straight to the gateway; we only receive the payment URL and status callbacks. Consult your QSA for the mapping that applies to your business.
Bisa dipakai white-label untuk klien?Can I white-label it for clients?
Ya. API key bersifat merchant-scoped dan kredensial gateway bisa disimpan per merchant, jadi satu klien satu isolasi. Hubungi kami untuk penawaran agency.Yes. API keys are merchant-scoped and gateway credentials can be stored per merchant, so each client gets its own isolation. Contact us for agency pricing.
Siapa yang mengoperasikan ini?Who operates this?
Tim BerkahKarya (CV Graha Insan Mandiri Berkah). Layanan berjalan di PM2 dengan auto-restart dan health check; endpoint /health publik melaporkan status database dan jumlah gateway terkonfigurasi.The BerkahKarya team (CV Graha Insan Mandiri Berkah). The service runs under PM2 with auto-restart and health checks; the public /health endpoint reports database status and how many gateways are configured.
